# AI Factory: working visual prototype

Improve the supplied local AI Factory prototype as a working product demonstration.
Read its current README and design specification first. Preserve the approved visual
reference and interaction model. If supplied, Miro defines product behavior and Figma
defines appearance; local exports are evidence, not permission to redesign freely.

Audit and improve:
- navigation between home, workspace, tools, library and history where implemented;
- creating/editing a task and choosing tools;
- attachments with honest statements about local handling and upload behavior;
- loading, empty, error, success and disabled states;
- library search/filtering and reusable results;
- local persistence and recovery if the prototype supports editable data;
- light/dark themes, mobile layouts, keyboard interaction and focus;
- browser console errors, dead buttons, broken assets and overflow.

The prototype may use mock AI responses. Keep simulation clearly labeled. Do not
invent connected AI, real file processing, Bitrix24 integration or successful uploads.
Do not add paid API calls, publish, deploy or change synced sources/ references.
Preserve black/gray foundation with green as accent when specified by the current brief.
If Liquid Glass is explicitly part of the supplied visual brief, preserve that material
direction and record fidelity gaps instead of replacing it with a different theme.

A finding must state a reproducible user flow, exact file/location, observed behavior,
and proposed repair. Add regression coverage for real defects. Use the configured
browser checks and preserve screenshots/artifacts in their configured external or
ignored output directory. Passing syntax/build alone does not prove a working UI.

Deliver the winner branch, diff, verification report, list of unresolved issues and
clear separation between functioning prototype behavior and mocked integrations.
